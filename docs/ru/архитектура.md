# Архитектура

Этот документ объясняет, что происходит между моментом, когда ваше тело возмущает WiFi-сигнал, и моментом, когда в дашборде загорается точка.

## Этап 1: WiFi → CSI

Ноды ESP32 работают как **пассивные мониторы** вашей WiFi-сети. Когда любой пакет летит между устройством и AP, WiFi-радио ESP32 извлекает [Channel State Information](https://en.wikipedia.org/wiki/Channel_state_information) — комплексный снимок среды распространения по поднесущим.

Формат: 64 поднесущие (HT20) или 256 (HT40), комплексный int8 на поднесущую, ~100 Гц обновление.

## Этап 2: ESP32 → сервер (csi-ingest)

Каждая нода:

1. Буферизует CSI-кадры по 1 КБ.
2. Ставит PTP-таймстамп.
3. Шифрует ChaCha20-Poly1305 на mesh-PSK.
4. Пушит через WebSocket (TLS по умолчанию) на edge-сервер.

`csi-ingest` запускает axum-WebSocket-хендлер, расшифровывает, парсит protobuf, складывает в Tokio-канал по ноде.

## Этап 3: DSP-pipeline

`dsp` превращает сырое CSI в устойчивые модели-friendly представления:

1. **Калибровка** — снимаем постоянные смещения фазы / амплитуды по поднесущим.
2. **Фильтрация** — low-pass для шума, bandpass для дыхания / пульса.
3. **FFT / STFT** — короткое преобразование Фурье на потоке амплитуд.
4. **Doppler** — фаза-приращение между соседними кадрами → радиальная скорость.
5. **Вычитание фона** — отнимаем clutter-карту пустой комнаты.

Выход: `DspFrame` с амплитудой, фазой, Doppler и метаданными.

## Этап 4: Multi-node fusion

`fusion` берёт time-aligned `DspFrame` от N нод и крутит multi-source Extended Kalman Filter:

- Состояние: позиция, скорость, motion-класс на каждую отслеживаемую сущность.
- Наблюдение: направление сигнальной энергии + UWB AoA + BLE RSSI.
- Process noise настроен по классу.

Выход: `FusedScene` с нулём или больше отслеживаемых сущностей и доверительными интервалами.

## Этап 5: Inference

`inference` запускает Candle (или ONNX Runtime через feature-flag) на fused scene:

- Presence (binary + confidence)
- Pose (17 keypoints + per-keypoint visibility)
- Vital signs (HR, BR + confidence bands)
- Activity (sit/stand/walk/lie/fall)
- Sleep stage (Wake/Light/Deep/REM)

Все головы делят общий 128-d encoder; задача-специфичны только головы. Модели версионируются, лежат в `server/models/`.

## Этап 6: API и дашборд

`api` экспонирует:

- **REST**: `/api/v1/scene`, `/api/v1/vitals` и т.д.
- **WebSocket**: `/api/v1/stream` — лайв-обновления.
- **gRPC**: `wavesight.v1.SceneService` для power users.

Дашборд подписывается на `/api/v1/stream` и рендерит сцену в 3D через React Three Fiber.

## Где хранится что

- **Сырое CSI**: 24-часовой rolling buffer в SQLite, потом агрегаты.
- **Агрегаты**: бессрочно в Parquet под `~/.wavesight/data/`.
- **Модели**: `server/models/`, версионируются по semver.
- **Конфиг**: TOML в `~/.config/wavesight/config.toml`.

## Чего в архитектуре НЕТ

- Никакого облачного round-trip в дефолтном деплое.
- Никакого постоянного видео.
- Никакого identity-inference сверх того, что вы явно включите.

Детали — в [ADR](../adr/).
