# Вертикали

WaveSight поставляется с тремя production-ready вертикалями. Каждая
живёт в `examples/<имя>/` и использует одно и то же ядро платформы.

## EldGuard — детекция падений

Push-уведомления в мобильное приложение когда пожилой человек упал.
Доступ для семьи. Без камер дома, без облака, без носимых устройств.

- **Аудитория**: взрослые дети пожилых родителей.
- **Inference-голова**: `fall` (latency-optimised).
- **Mobile**: Flutter, push через APNs / FCM.
- **Telegram**: опциональный мост для дальних родственников.

Документация: [`examples/eldguard/`](../../examples/eldguard/).

## SleepWave — стадирование сна

4-стадийная гипнограмма (Wake / Light / Deep / REM) с одной ESP32 в
спальне. Ежеутренний PDF-отчёт. Только локально.

- **Аудитория**: quantified-self, sleep-хакеры.
- **Inference-голова**: `sleep`.
- **Сравнение**: целимся в ~70 % согласия с Withings ScanWatch.

Документация: [`examples/sleepwave/`](../../examples/sleepwave/).

## PresenceOS — occupancy для Home Assistant

Поком­натное присутствие как `binary_sensor` в Home Assistant с
sub-second задержкой. Видит неподвижных людей (сидят, читают) — где
PIR-датчики бесполезны.

- **Аудитория**: пользователи smart-home автоматизаций.
- **Inference-голова**: `presence`.
- **Интеграция**: нативная HACS-интеграция + MQTT discovery.

Документация: [`examples/presence-os/`](../../examples/presence-os/).

## Почему три, а не одна

Платформу сложно оценить без конкретных вариантов использования.
Параллельная разработка трёх вертикалей вынуждает архитектурные
решения честно отрабатывать сквозные concerns (uncertainty, latency,
аутентификация, push). В single-vertical-проекте такие решения
обычно прячутся в платформе и потом ломаются.

Вертикали разделяют:

- Одни и те же типы `wavesight-core`.
- Один и тот же pipeline `csi-ingest` → `dsp` → `fusion`.
- Один и тот же дашборд.

Вертикали отличаются:

- Какой inference-головой пользуются.
- Каким downstream UI пользуются (mobile push vs PDF vs HA entity).
- Методикой оценки (FPR vs accuracy vs latency).
